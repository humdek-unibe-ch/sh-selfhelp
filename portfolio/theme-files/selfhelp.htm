SelfHelp

Build, run and automate web and mobile studies, interventions and self-help programmes – without writing code.

SelfHelp Summary

  • Compose pages from ready-made styles – 69 in the core, more from every plugin – directly in the browser
  • Collect answers with forms, surveys and experiments in one structured data model
  • Show data back to participants as dashboards, progress feedback and personalised texts
  • Automate e-mails, push notifications and reminders with form actions and scheduled jobs
  • Decide with a visual condition builder who sees what – and when
  • Run every study in as many languages as you need
  • Protect data with roles, groups, page-level permissions and two-factor authentication
  • Extend the system with 15 public plugins: SurveyJS, lab.js, Qualtrics, R, Plotly, LLM chat and more
  • Serve one set of pages as a responsive website and as JSON for mobile apps
  • Open source (Mozilla Public License 2.0) – vanilla PHP and MySQL, no framework to learn
  • Studies built with SelfHelp are reported in 15 journal articles – clinical psychology, health behaviour change and education

The story behind SelfHelp

SelfHelp is a web platform for research experiments and intervention studies, developed at the University of Bern. Instead of building a new application for every study, researchers describe it: pages, forms, texts, rules and reminders are data in a database and are edited in the browser. SelfHelp is now in its seventh major version and is extended by a growing family of plugins.

Idea
One platform instead of a custom application per study. Every study gets a clean website and a mobile-ready interface from the same configuration.
Goals
  • Let researchers build and change a study without a developer
  • Store every answer in a structure that is ready for analysis
  • Keep participants engaged with reminders and personal feedback
  • Protect sensitive data with fine-grained permissions
  • Stay open: open source and extensible through plugins and hooks
Open source
The code, the releases and all public plugins are available on GitHub – see the links at the bottom of this page.

01 · Build

One system, two sides

SelfHelp separates what you edit from what participants see. Authors work in a browser-based editor; participants get a clean, responsive website – and the very same pages are available as JSON for the mobile app.

Pages, sections, styles, fields, routes and permissions are stored in the database. A study can therefore be changed live, exported as JSON and imported into another installation.

Build pages from blocks

A page is a tree of sections. Every section has a style – container, card, markdown, form, progress bar and many more – and every style brings its own fields.

  • Add, move and delete sections in place
  • Filter the tree by name, style or text
  • Edit every field in a side panel
  • Import and export pages as JSON

77 ready-made styles

Layout containers, navigation, forms, inputs, media, lists, text, conditional containers, account pages and more. Each style renders HTML for the web and JSON for the mobile app. In the demo installation shown here the core ships 69 styles and four plugins (SurveyJS, lab.js, LLM and the formula parser) add eight more.

Every style is a small component built from a model, a view and an optional controller – adding your own follows the same pattern.

Every language, one page

Each field holds one translation per language. Switch the language and everything follows – menus, headings, form questions and answer options.

Participants choose their language with the language picker. The demo study shown here runs in German, English and French.

02 · Collect

Forms that store structured data

Combine inputs, sliders, radio buttons, selects, check boxes and text areas into forms. Record forms keep one entry per participant and update it on every save; log forms append a new entry each time – ideal for diaries and repeated measures.

Answers are validated on the server and stored as data you can query. Every save can also trigger automation.

Surveys and experiments

The SurveyJS plugin adds a drag-and-drop survey designer with live preview, themes, logic, translations, versions and a results dashboard. For behavioural tasks, the lab.js plugin runs experiments in the browser and stores the results like any other form.

Prefer Qualtrics? The Qualtrics plugin manages surveys and processes their responses.

One data model for everything

Forms, surveys, experiments, AI chats, API calls and wearables all write through the same four tables: dataTables, dataCols, dataRows and dataCells. A new form simply defines new columns – no new database table is needed.

Each record keeps its participant, a timestamp and the trigger that saved it (started, updated, finished or deleted). Reading pivots the cells back into a table with one row per record.

Browse and export every answer

Every form and survey gets its own table in the admin area. Search, sort and copy or export to CSV and Excel with one click.

The same data feeds dashboards, reports and automation.

03 · Use the data

Show data back to participants

A data config loads records into a section – the first, the last or all of them, for the logged-in participant or for everyone. Text fields accept placeholders such as {{last.mood}}, and lists repeat for every record.

Dashboards, progress feedback and personalised messages need no custom code.

The right content for the right person

A visual condition builder combines rules with AND / OR and nests groups as deep as needed. Rules can check the user group, form field values, the current date or time, the page, the platform, the language or the last login – and are stored as JsonLogic.

Attach them to sections, navigation entries, form actions and scheduled jobs.

04 · Automate

From one tap to the right message

A form action watches a form or survey. When it is started, updated, finished or deleted, the action checks its rules and schedules jobs: an e-mail right away, a push notification tomorrow, a reminder on Monday at 09:00.

No scripts to write – the job scheduler queues and executes mails, push notifications and tasks, and every change is written to the audit trail.

Configure automation in the browser

Group jobs into blocks, randomise participants into blocks or limit them to target groups. A job can send an e-mail or push notification, run a custom task or add and remove the participant from a group.

Schedule jobs immediately, at a fixed date and time, after a period from seconds to months, or on a chosen weekday and time. Messages support placeholders such as @user_name, and reminders can repeat until a date.

A transparent job queue

The scheduled-jobs module lists what is queued and what is done, with entry date, planned date and actual execution date. Run the queue on demand, compose a one-off e-mail or notification, or open the calendar view.

Copy or export the list to CSV or Excel.

05 · Protect and extend

Fine-grained access control

Users belong to groups and database roles. For every role you decide, page by page and module by module, who may select, insert, update or delete – and whether two-factor authentication is required.

Every change in the system is written to the transactions audit trail.

AI built in – on your terms

The LLM plugin adds an AI chat component, scripts and AI-enhanced forms. Connect self-hosted models or any OpenAI-compatible endpoint, set defaults for model, temperature and token limits, and keep conversations, scripts and memory in one admin console.

Safety checks detect critical keywords and can block a conversation. Further plugins add a therapist and patient chat with AI drafts and a multi-persona agent chat.

Fifteen plugins – and your own

Plugins extend the core without touching it. Each plugin lives in its own repository, ships its own SQL migrations and version number and registers styles, admin modules, jobs and hooks.

Hooks let a plugin run alongside a core method or replace its result – and several hooks can chain – so even deep behaviour can be adapted without editing core files.

06 · Everywhere and open

Web, mobile and API

Pages are responsive on the web, and every style also renders JSON for the mobile app. Push notifications reach participants on their phones.

The REST API plugin exposes data tables to apps and external systems with API keys.

A small core, built to be extended

SelfHelp is vanilla PHP 8.2+ and MySQL 8 on Apache, with jQuery and Bootstrap 4.6 in the browser, APCu caching and Clockwork profiling. A service container hands out the database, router, access control, user input, job scheduler and condition services.

The database is the application contract: pages, styles, fields, hooks and permissions live in it and are versioned by SQL migrations. SelfHelp is open source under the Mozilla Public License 2.0.

07 · Research

Research built with SelfHelp

SelfHelp was built for research experiments and intervention studies – and research is where it shows its strength. The journal articles below report studies and study protocols that were built with SelfHelp: randomised controlled trials of internet interventions, micro-randomised and full factorial designs, co-design projects and field studies in schools.

They cover clinical psychology and internet interventions (7), health behaviour and digital interventions (4) and education and learning (4), and every entry links to its DOI.
